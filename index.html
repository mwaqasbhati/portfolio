My approach

Wherever the product is today, there's a sensible first move

It's simple: understand the situation honestly before touching anything.

If you already have code

I understand it before I change it

No rewrites for the sake of it. I learn how the product actually behaves first, then change it deliberately.

If another developer built it

I find out what's really there

A straight technical review: what works, what's fragile, what needs attention now versus later.

If AI generated most of it

If you only have an idea
